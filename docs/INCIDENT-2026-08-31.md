- GitHub exposes no definitive reason for the missing scheduled events. Its official documentation permits delayed/dropped scheduled runs under load. The `timezone: America/New_York` syntax is supported; removing it as an alleged syntax fix would be incorrect. The precise scheduler cause remains unconfirmed.

The earlier maintenance verification exercised manual execution, not a completed overnight scheduled rollover. This repair addresses that operational gap without claiming a provider-level root cause.

## Repairs

1. Daily catch-up attempts now run at :11 and :41 each hour, seven days a week, including after midnight and during daytime. Successful weekly runs still trigger the daily workflow.
2. A read-only full-content gate skips generation, candidate upload and publishing when today's prepared reflection, reviewed saint, daily JSON, dated snapshot and archive indexes already match. A date match alone is insufficient. A new Eastern day or a same-day correction is detected.
3. Existing queued writers, fresh-main reconciliation, validation, midnight safety checks and ordinary non-forced pushes remain in place. Missing local reviewed saints are not silently invented. Monthly saints remain operator-reviewed and manual.
4. Health checks repeat at :17 and :47 each hour. The 06:00 Eastern deadline remains; reports now distinguish current content from a tolerated previous-day result before the deadline. The first post-deadline schedule is 06:17, not a guaranteed execution time.
5. README and the publishing runbook now explain recovery, no-op results and scheduling limitations. The independent desktop check remains Monday–Friday at 09:15 Eastern.
